## Merge

Está permitido leer `"$VAR_S1_FILE"` únicamente para obtener variables necesarias de este paso.

Está permitido leer `"$ANALYSIS_FILE"` únicamente como fuente de verdad para el contenido funcional y técnico de este paso.

No está permitido usar ninguna otra fuente.

Objetivo:

Generar `MERGE_TITLE.txt` y `merge.txt` dentro de `"$OUTPUT_DIR"` usando exclusivamente `"$ANALYSIS_FILE"` como fuente de verdad para el contenido de cambios.

- `MERGE_TITLE.txt` debe contener únicamente la frase principal del merge
- `merge.txt` debe contener únicamente el cuerpo del merge

El contenido debe ser un **mensaje editorial técnico** que resuma el impacto de la publicación en `main`, incluyendo viñetas detalladas y referencia al Pull Request.

Las variables del flujo solo podrán utilizarse para metadatos estrictamente necesarios como ramas, versión y nombres de archivo. Queda prohibido inferir cambios desde otras fuentes.

### 6.1 Validar directorio de salida de merge

Leer `"$VAR_S1_FILE"` para obtener:

- `OUTPUT_DIR`
- `CURRENT_BRANCH`
- `TARGET_BRANCH`
- `RELEASE_VERSION`

Reglas:

- no inventar variables
- `OUTPUT_DIR` debe venir definido desde pasos anteriores

Definir:

- `MERGE_TITLE_FILE="$OUTPUT_DIR/MERGE_TITLE.txt"`
- `MERGE_FILE="$OUTPUT_DIR/merge.txt"`

Acción:

`mkdir -p "$OUTPUT_DIR"`

Abortar si:

- `OUTPUT_DIR` no existe o está vacío
- `CURRENT_BRANCH` no existe o está vacío
- `RELEASE_VERSION` no existe o está vacío
- no puede crearse `"$OUTPUT_DIR"`

### 6.2 Leer análisis para merge

Leer `"$ANALYSIS_FILE"` y usarlo como única fuente de verdad para identificar los ejes principales de la publicación.

---

### 6.3 Generar borrador de MERGE_TITLE.txt y merge.txt

#### MERGE_TITLE.txt

**El título debe ser exactamente:**

```text
Publish release <RELEASE_VERSION> to main
```

#### merge.txt

Formato de salida requerido para `merge.txt` (Mensaje editorial):

```markdown
Final publication of version <RELEASE_VERSION>. This release consolidates the following technical and functional milestones:

- {Milestone 1 derived from Analysis}
- {Milestone 2 derived from Analysis}
- ...

#PR: {PR_NUMBER_OR_LINK_IF_AVAILABLE}
```

Reglas para `merge.txt`:

- redactar de forma editorial y técnica
- incluir al menos 3 viñetas descriptivas basadas en el análisis
- incluir la etiqueta `#PR:` al final
- no inventar información fuera del análisis

Abortar si:

- `MERGE_TITLE.txt` no es exactamente `Publish release <RELEASE_VERSION> to main`
- `merge.txt` no contiene al menos 3 viñetas basadas en hechos del análisis

---

### 6.4 Escribir MERGE_TITLE.txt y merge.txt

Crear o sobrescribir:

- `"$MERGE_TITLE_FILE"`
- `"$MERGE_FILE"`

---

### 6.5 Resultado de merge

Mostrar:

- `"$MERGE_TITLE_FILE"`
- `"$MERGE_FILE"`
