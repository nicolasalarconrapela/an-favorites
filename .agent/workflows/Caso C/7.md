# Textos de Merge · Caso C

Este paso continúa el flujo anterior.
Usar el contexto generado en el workflow previo.
Continuar con las variables generadas en el paso anterior.

---

## Rol

Actúa como un **Technical Lead experto en releases, GitHub Pull Requests y redacción técnica de historial Git**.

---

## Merge

Está permitido leer `"$VAR_S1_FILE"` únicamente para obtener variables necesarias de este paso.

Está permitido leer `"$ANALYSIS_FILE"` únicamente como fuente de verdad para el contenido funcional y técnico de este paso.

No está permitido usar ninguna otra fuente.

---

## Objetivo

Generar `MERGE_TITLE.txt` y `merge.txt` dentro de `"$OUTPUT_DIR"` para la integración desde `"$CURRENT_BRANCH"` hacia `main`.

- `MERGE_TITLE.txt` debe contener únicamente la frase editorial técnica del merge
- `merge.txt` debe contener únicamente el cuerpo del merge

El contenido debe ser un **mensaje editorial técnico** que resuma el impacto de la publicación en `main`, incluyendo viñetas técnicas concretas y referencia al número de Pull Request.

---

### 6.1 Validar directorio de salida de merge

Leer `"$VAR_S1_FILE"` para obtener:

- `OUTPUT_DIR`
- `CURRENT_BRANCH` → debe cumplir exactamente `^releases/[0-9]+\.[0-9]+\.[0-9]+$`
- `TARGET_BRANCH` → debe ser exactamente `main`
- `RELEASE_VERSION` → versión objetivo (ej. `1.3.0`)
- `PR_NUMBER` → número de Pull Request obtenido del paso anterior (puede ser `N/A` si aún no se creó el PR)

Reglas:

- no inventar variables
- `OUTPUT_DIR` debe venir definido desde pasos anteriores
- la rama origen debe cumplir `^releases/[0-9]+\.[0-9]+\.[0-9]+$`
- la rama destino debe ser exactamente `main`

Definir:

- `MERGE_TITLE_FILE="$OUTPUT_DIR/MERGE_TITLE.txt"`
- `MERGE_FILE="$OUTPUT_DIR/merge.txt"`

Acción:

`mkdir -p "$OUTPUT_DIR"`

Abortar si:

- `OUTPUT_DIR` no existe o está vacío
- `CURRENT_BRANCH` no cumple `^releases/[0-9]+\.[0-9]+\.[0-9]+$`
- `TARGET_BRANCH` no es exactamente `main`
- `RELEASE_VERSION` no existe o está vacío
- no puede crearse `"$OUTPUT_DIR"`

### 6.2 Leer análisis para merge

Leer `"$ANALYSIS_FILE"` y usarlo como única fuente de verdad para identificar los 2 o 3 hitos técnicos más importantes de la release.

Abortar si:

- `"$ANALYSIS_FILE"` no existe
- `"$ANALYSIS_FILE"` está vacío

---

### 6.3 Generar MERGE_TITLE.txt y merge.txt

#### MERGE_TITLE.txt

**El título debe ser una frase editorial técnica** que cumpla TODAS estas reglas:

- No usar `Merge pull request #...`
- No usar variantes genéricas como `Stabilize release...`, `Consolidate release...`, `Publish release X to main`
- Debe resumir en una frase los 2 o 3 hitos técnicos más importantes visibles en `"$ANALYSIS_FILE"`
- Debe incluir al final `#<PR_NUMBER>` (si `PR_NUMBER` está disponible; si no, omitirlo)
- Debe ser concisa, técnica y editorial
- Una única línea sin bloque markdown

Ejemplo de estructura (no copiar literalmente, generar desde el análisis real):

```text
<Acción editorial técnica que resume los hitos> #<PR_NUMBER>
```

Ejemplo orientativo:

```text
Land gitignore management, release notifications and panel UX improvements #42
```

Abortar si:

- `MERGE_TITLE.txt` contiene más de una línea
- `MERGE_TITLE.txt` empieza con `Merge pull request`
- `MERGE_TITLE.txt` es la frase genérica `Publish release <RELEASE_VERSION> to main`

#### merge.txt

El cuerpo del merge debe ser un conjunto de bullets técnicos concretos que:

- No dupliquen literalmente el cuerpo de `PR.txt`
- No usen frases genéricas como "various improvements" o "bug fixes"
- Estén derivados directa y exclusivamente de `"$ANALYSIS_FILE"`
- Incluyan al menos 3 bullets descriptivos basados en hechos del análisis

Formato de salida requerido para `merge.txt`:

```markdown
- <bullet técnico 1 derivado del análisis>
- <bullet técnico 2 derivado del análisis>
- <bullet técnico 3 derivado del análisis>
```

Reglas para `merge.txt`:

- `merge.txt` contiene únicamente el cuerpo del merge
- no duplicar la frase principal dentro del body
- sin secciones markdown (`##`, `###`, `Summary`)
- sin metadatos de ramas, versión ni directorio
- viñetas breves, una idea técnica por línea
- cada viñeta debe comenzar con guion y espacio (`-` seguido de espacio)
- no crear viñetas vacías o genéricas
- no inventar información fuera del análisis

Abortar si:

- `merge.txt` no contiene al menos 3 viñetas basadas en hechos del análisis
- `merge.txt` incluye la frase principal dentro del body

---

### 6.4 Escribir MERGE_TITLE.txt y merge.txt

Crear o sobrescribir:

- `"$MERGE_TITLE_FILE"`
- `"$MERGE_FILE"`

Abortar si:

- no puede escribirse `"$MERGE_TITLE_FILE"`
- no puede escribirse `"$MERGE_FILE"`

---

### 6.5 Resultado de merge

Mostrar:

- `"$MERGE_TITLE_FILE"`
- `"$MERGE_FILE"`

Mostrar además un resumen breve indicando:

- frase editorial técnica del merge generada
- rama origen
- rama destino: `main`
- directorio de salida utilizado
