# Creación de Pull Request y Merge · Caso C

Este paso continúa el flujo anterior.
Usar el contexto generado en el workflow previo.
Continuar con las variables generadas en el paso anterior.

Este paso es crítico y debe ejecutarse con validación estricta de ramas, estado limpio del repositorio, fuentes permitidas, ejecución controlada y validación obligatoria del enlace y resultado final.

## Objetivo

Preparar y, tras autorización explícita del usuario, ejecutar:

1. La creación del Pull Request desde `"$CURRENT_BRANCH"` (`releases/$RELEASE_VERSION`) hacia `main`
2. El merge del Pull Request usando el mensaje editorial técnico generado

Utiliza exclusivamente los ficheros generados para título, cuerpo del PR y mensaje de merge.

Reglas generales:

- la rama origen debe cumplir exactamente `^releases/[0-9]+\.[0-9]+\.[0-9]+$`
- la rama destino debe ser exactamente `main`
- el título del Pull Request debe provenir exclusivamente de `PR_TITLE.txt`
- el cuerpo del Pull Request debe provenir exclusivamente de `PR.txt`
- el título del merge debe provenir exclusivamente de `MERGE_TITLE.txt`
- el cuerpo del merge debe provenir exclusivamente de `merge.txt`
- no está permitido regenerar manualmente ningún contenido en este paso
- este paso funciona en modo previsualización obligatoria
- antes de ejecutar cualquier comando, preguntar siempre al usuario y esperar autorización explícita
- no se podrá ejecutar ningún comando sin autorización explícita posterior del usuario
- la ejecución debe limitarse a un único comando por vez
- si el comando autorizado falla, detener inmediatamente el flujo
- si el comando autorizado falla, no reintentar, no corregir automáticamente y no ejecutar ningún otro comando adicional
- si el comando autorizado falla, mostrar el error y esperar nuevas instrucciones del usuario

---

### 8.1 Validar rama actual y estado seguro del repositorio

Leer las variables necesarias del fichero autorizado del flujo: `"$VAR_S1_FILE"`.

Validar obligatoriamente:

- `CURRENT_BRANCH` existe y no está vacía
- `CURRENT_BRANCH` cumple exactamente `^releases/[0-9]+\.[0-9]+\.[0-9]+$`
- `TARGET_BRANCH` es exactamente `main`
- `RELEASE_VERSION` existe y no está vacía
- no hay archivos modificados sin commit que afecten al flujo fuera de `.agent/**` y `out_tmp/**`

Reglas:

- no aceptar ramas origen que no cumplan `^releases/[0-9]+\.[0-9]+\.[0-9]+$`
- no aceptar ramas destino distintas de `main`
- para validar el estado local, ignorar explícitamente `.agent/**` y `out_tmp/**`
- los cambios dentro de `.agent/**` y `out_tmp/**` no deben bloquear el flujo
- cualquier otro cambio local fuera de esas rutas sí debe bloquear el flujo
- no ejecutar ningún comando operativo en este paso
- este paso solo puede preparar una previsualización de validaciones y comandos

Abortar si:

- `CURRENT_BRANCH` no cumple el patrón `^releases/[0-9]+\.[0-9]+\.[0-9]+$`
- `TARGET_BRANCH` no es `main`
- existe cualquier cambio local sin commit fuera de `.agent/**` y `out_tmp/**`

---

### 8.2 Fuente obligatoria para el Pull Request y el Merge

Está permitido leer únicamente:

- `"$PR_TITLE_FILE"` como título del Pull Request (exactamente `Publish release <RELEASE_VERSION>`)
- `"$PR_FILE"` como cuerpo del Pull Request
- `"$MERGE_TITLE_FILE"` como título editorial del merge
- `"$MERGE_FILE"` como cuerpo del merge
- `"$VAR_S1_FILE"` para validaciones de contexto

Reglas:

- verificar que el título en `"$PR_TITLE_FILE"` es exactamente `Publish release <RELEASE_VERSION>`
- si el título no coincide con ese patrón, abortar
- verificar que `"$MERGE_TITLE_FILE"` no empieza con `Merge pull request`
- si `"$PR_TITLE_FILE"` no existe o está vacío, abortar
- si `"$PR_FILE"` no existe o está vacío, abortar
- si `"$MERGE_TITLE_FILE"` no existe o está vacío, abortar
- si `"$MERGE_FILE"` no existe o está vacío, abortar

---

### 8.3 Crear Pull Request

Objetivo:

Preparar y, tras autorización explícita del usuario, ejecutar la creación del Pull Request desde `CURRENT_BRANCH` hacia `main`.

Definir:

- rama origen: `CURRENT_BRANCH`
- rama destino: `main`
- título: contenido de `"$PR_TITLE_FILE"`
- cuerpo: contenido de `"$PR_FILE"`
- `PR_LINK_FILE="$OUTPUT_DIR/PR_LINK.txt"`
- `PR_NUMBER_FILE="$OUTPUT_DIR/PR_NUMBER.txt"`

Mostrar previsualización antes de ejecutar:

```text
Operación prevista: crear Pull Request
  Rama origen:  <CURRENT_BRANCH>
  Rama destino: main
  Título:       <contenido de PR_TITLE.txt>
  Cuerpo:       <contenido de PR.txt>
```

Comando permitido:

```bash
gh pr create --base main --head "$CURRENT_BRANCH" --title "$(cat "$PR_TITLE_FILE")" --body-file "$PR_FILE"
```

Reglas:

- no ejecutar todavía el comando real hasta obtener autorización explícita del usuario
- indicar explícitamente que no se ha ejecutado ningún comando
- preguntar al usuario antes de ejecutar la creación real del Pull Request
- si el comando falla, detener inmediatamente el flujo
- tras ejecutar el comando autorizado, el resultado debe contener un único enlace válido de Pull Request de GitHub
- el resultado válido debe seguir el patrón `https://github.com/<owner>/<repo>/pull/<number>`
- el enlace obtenido debe guardarse obligatoriamente en `"$PR_LINK_FILE"`
- extraer el número del PR del enlace y guardarlo en `"$PR_NUMBER_FILE"` (solo el número, sin texto adicional)
- `"$PR_LINK_FILE"` debe contener únicamente una línea con la URL del Pull Request
- `"$PR_NUMBER_FILE"` debe contener únicamente el número del PR
- no está permitido continuar el flujo si no existe un enlace válido y guardado

Abortar si:

- el comando no devuelve una URL de Pull Request válida
- la URL no coincide con el patrón `https://github.com/<owner>/<repo>/pull/<number>`
- no puede guardarse `"$PR_LINK_FILE"` o queda vacío
- no puede extraerse o guardarse el número del PR en `"$PR_NUMBER_FILE"`

Salida requerida (tras ejecución autorizada y exitosa):

- mostrar el enlace del Pull Request creado
- mostrar la ruta de `"$PR_LINK_FILE"`
- mostrar el número del PR guardado en `"$PR_NUMBER_FILE"`
- indicar explícitamente que el enlace ha sido validado y guardado
- esperar autorización explícita del usuario para continuar con el merge

---

### 8.4 Merge del Pull Request

Objetivo:

Preparar y, tras autorización explícita del usuario, ejecutar el merge del Pull Request usando el mensaje editorial técnico generado en el paso 7.

Leer `"$PR_NUMBER_FILE"` para obtener el número del PR.

Mostrar previsualización antes de ejecutar:

```text
Operación prevista: merge del Pull Request
  PR número:       <PR_NUMBER>
  Título del merge: <contenido de MERGE_TITLE.txt>
  Cuerpo del merge: <contenido de merge.txt>
  Estrategia:      --merge (merge commit)
```

Comando permitido:

```bash
gh pr merge <PR_NUMBER> --merge --subject "$(cat "$MERGE_TITLE_FILE")" --body "$(cat "$MERGE_FILE")"
```

Reglas:

- no ejecutar todavía el comando real hasta obtener autorización explícita del usuario
- la estrategia de merge debe ser `--merge` (merge commit); no usar `--squash` ni `--rebase` salvo que el usuario lo solicite explícitamente
- el título del merge debe provenir exclusivamente de `"$MERGE_TITLE_FILE"`
- el cuerpo del merge debe provenir exclusivamente de `"$MERGE_FILE"`
- si el comando falla, detener inmediatamente el flujo
- no reintentar ni corregir automáticamente
- tras el merge exitoso, verificar que el PR está en estado `merged`

Verificación requerida tras el merge:

```bash
gh pr view <PR_NUMBER> --json state --jq .state
```

La salida debe ser exactamente `MERGED`.

Abortar si:

- `"$PR_NUMBER_FILE"` no existe o está vacío
- el número del PR no puede obtenerse
- el comando de merge falla
- el estado del PR no es `MERGED` tras la verificación

Salida requerida (tras ejecución autorizada y exitosa):

- mostrar el estado del PR: `MERGED`
- mostrar el título de merge utilizado
- confirmar que el merge se realizó con el mensaje editorial técnico correcto
- esperar confirmación del usuario antes de continuar

---

### 8.5 Resultado

Mostrar:

- rama origen: `CURRENT_BRANCH`
- rama destino: `main`
- versión de release: `RELEASE_VERSION`
- enlace del Pull Request creado
- número del Pull Request
- estado del PR: `MERGED`
- fichero donde se ha guardado el enlace del Pull Request: `"$PR_LINK_FILE"`
- confirmación de que no se ha ejecutado ningún comando sin autorización explícita

Abortar si:

- no existe `"$PR_LINK_FILE"` o está vacío
- el contenido de `"$PR_LINK_FILE"` no es un enlace válido de Pull Request

Esperar confirmación explícita del usuario antes de continuar con cualquier paso posterior.
