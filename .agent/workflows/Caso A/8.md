## Fase 1: Creación de Pull Request de release hacia develop

Este paso continúa el flujo anterior.
Usar el contexto generado en el workflow previo.
Continuar con las variables generadas en el paso anterior.

Este paso es crítico y debe ejecutarse con validación estricta de ramas, estado limpio del repositorio, fuentes permitidas, ejecución controlada y validación obligatoria del enlace resultante.

### Objetivo

Preparar y, tras autorización explícita del usuario, ejecutar la creación del Pull Request desde una rama `release/1.Y.x` hacia `develop`, utilizando exclusivamente los ficheros generados para título y cuerpo del Pull Request.

Reglas generales:

- la rama origen debe ser una rama `release/1.Y.x`
- la rama destino debe ser exactamente `develop`
- el título del Pull Request debe provenir exclusivamente de `PR_TITLE.txt`
- el cuerpo del Pull Request debe provenir exclusivamente de `PR.txt`
- no está permitido regenerar manualmente el contenido del Pull Request en este paso
- este paso funciona en modo previsualización obligatoria
- antes de ejecutar cualquier comando, preguntar siempre al usuario y esperar autorización explícitamente
- no se podrá ejecutar ningún comando sin autorización explícita posterior del usuario
- la ejecución debe limitarse a un único comando por vez
- si el comando autorizado falla, detener inmediatamente el flujo
- si el comando autorizado falla, no reintentar, no corregir automáticamente y no ejecutar ningún otro comando adicional
- si el comando autorizado falla, mostrar el error y esperar nuevas instrucciones del usuario
- tras la ejecución autorizada, el resultado debe devolver un enlace válido de Pull Request
- dicho enlace debe guardarse obligatoriamente
- si no se obtiene un enlace válido y guardado, detener inmediatamente el flujo

---

### 8.1 Validar rama actual y estado seguro del repositorio

Leer las variables necesarias del fichero autorizado del flujo.

Objetivo:

Garantizar que el flujo parte de una rama válida y que no existen cambios locales pendientes relevantes antes de preparar ninguna operación.

Validar obligatoriamente:

- `CURRENT_BRANCH` existe y no está vacía
- `CURRENT_BRANCH` cumple exactamente la expresión `^release/1\.[0-9]+\.x$`
- el valor `Y` de la rama `release/1.Y.x` es mayor que la última release conocida
- `RELEASE_VERSION` existe y no está vacía
- no hay archivos modificados sin commit que afecten al flujo
- no hay archivos staged pendientes de commit que afecten al flujo
- no hay archivos untracked que afecten al flujo

Reglas:

- no aceptar ramas como `main`, `master`, `feature/*`, `hotfix/*` o cualquier otra distinta de `release/1.Y.x`
- la rama destino debe ser exactamente `develop`
- para validar el estado local, deben ignorarse explícitamente los directorios `.agent/**` y `out_tmp/**`
- los cambios dentro de `.agent/**` y `out_tmp/**` no deben bloquear el flujo
- cualquier otro cambio local fuera de esas rutas sí debe bloquear el flujo
- no ejecutar ningún comando en este paso
- no crear Pull Request
- no cambiar de rama
- no hacer `push`
- no ejecutar comandos de Git, GitHub CLI o cualquier otra herramienta operativa sin preguntar antes al usuario
- este paso solo puede preparar una previsualización de validaciones y comandos
- si existen cambios sin commit fuera de `.agent/**` y `out_tmp/**`, el flujo debe detenerse antes de cualquier operación

Abortar si:

- `CURRENT_BRANCH` no cumple la expresión `^release/1\.[0-9]+\.x$`
- el valor `Y` no es mayor que la última release conocida
- falta cualquiera de los datos obligatorios
- existe cualquier cambio local sin commit fuera de `.agent/**` y `out_tmp/**`
- existe cualquier cambio staged pendiente fuera de `.agent/**` y `out_tmp/**`
- existen archivos untracked que comprometen el flujo fuera de `.agent/**` y `out_tmp/**`
- se intenta ejecutar un comando sin haber preguntado antes al usuario
- se intenta ejecutar un comando sin autorización explícita del usuario

Salida requerida:

- mostrar el estado del árbol de trabajo
- mostrar la rama actual detectada
- mostrar la rama destino prevista: `develop`
- mostrar una previsualización de comprobaciones y comandos previstos
- indicar explícitamente que no se ha ejecutado ningún comando
- preguntar al usuario antes de cualquier ejecución real
- esperar autorización explícita del usuario antes de continuar

---

### 8.2 Fuente obligatoria para el Pull Request

Está permitido leer únicamente:

- `"$PR_TITLE_FILE"` como título del Pull Request
- `"$PR_FILE"` como cuerpo del Pull Request
- `"$VAR_S1_FILE"` para validaciones de contexto y metadatos mínimos

No está permitido usar ninguna otra fuente para construir el Pull Request.

Reglas:

- el Pull Request debe usar como título exactamente el contenido de `"$PR_TITLE_FILE"`
- el Pull Request debe usar como cuerpo exactamente el contenido de `"$PR_FILE"`
- no resumir de nuevo el análisis
- no rehacer el título
- no rehacer el cuerpo
- no añadir bloques nuevos no presentes en los ficheros generados
- no modificar el contenido salvo ajustes estrictamente técnicos de formato si el sistema de creación del Pull Request lo exige
- si `"$PR_TITLE_FILE"` no existe o está vacío, abortar
- si `"$PR_FILE"` no existe o está vacío, abortar
- no ejecutar todavía ningún comando de creación real
- este paso solo debe preparar una previsualización

Abortar si:

- `"$PR_TITLE_FILE"` no existe
- `"$PR_TITLE_FILE"` está vacío
- `"$PR_FILE"` no existe
- `"$PR_FILE"` está vacío
- no puede obtenerse un título válido desde `"$PR_TITLE_FILE"`
- no puede obtenerse un cuerpo válido desde `"$PR_FILE"`

Salida requerida:

- mostrar el título previsto del Pull Request
- mostrar el cuerpo previsto del Pull Request
- mostrar la rama origen prevista
- mostrar la rama destino prevista
- indicar explícitamente que no se ha ejecutado ningún comando

---

### 8.3 Crear Pull Request

Objetivo:

Preparar y, tras autorización explícita del usuario, ejecutar la creación del Pull Request desde la rama actual `release/1.Y.x` hacia `develop` utilizando exclusivamente el contenido de `"$PR_TITLE_FILE"` y `"$PR_FILE"`.

Definir:

- rama origen: `CURRENT_BRANCH`
- rama destino: `develop`
- título: contenido de `"$PR_TITLE_FILE"`
- cuerpo: contenido de `"$PR_FILE"`
- `PR_LINK_FILE="$OUTPUT_DIR/PR_LINK.txt"`

Reglas:

- no inventar título
- no inventar cuerpo
- no alterar la rama destino
- no crear el Pull Request contra otra rama distinta de `develop`
- si ya existe un Pull Request abierto con la misma rama origen y destino, no duplicarlo
- no ejecutar todavía el comando real de creación hasta obtener autorización explícita del usuario
- este paso solo debe mostrar la previsualización del comando exacto que se ejecutaría
- antes de ejecutar cualquier comando, preguntar al usuario
- solo está permitido ejecutar el comando exacto previamente mostrado en la previsualización y autorizado explícitamente por el usuario
- no está permitido ejecutar comandos alternativos, equivalentes, corregidos, abreviados o reconstruidos
- no está permitido encadenar comandos
- no está permitido ejecutar comandos auxiliares antes o después del comando aprobado
- no está permitido modificar argumentos, rutas, ramas, título o `body-file` sin nueva autorización explícita del usuario
- la ejecución debe ser siempre de un único comando por vez
- si el comando falla, detener inmediatamente el flujo
- si el comando falla, no ejecutar ningún otro comando posterior
- si el comando falla, no reintentar
- si el comando falla, no corregir automáticamente el comando
- si el comando falla, mostrar el error recibido y esperar nuevas instrucciones del usuario
- tras ejecutar el comando autorizado, el resultado debe contener un único enlace válido de Pull Request de GitHub
- el resultado válido debe seguir el patrón `https://github.com/<owner>/<repo>/pull/<number>`
- no se aceptan mensajes parciales, identificadores internos, texto descriptivo ni salidas sin enlace
- no se aceptan URLs de issues, commits, branches, compare, actions ni cualquier otro recurso distinto de un Pull Request
- el enlace obtenido debe guardarse obligatoriamente en `"$PR_LINK_FILE"`
- `"$PR_LINK_FILE"` debe contener únicamente una línea con la URL del Pull Request
- no está permitido continuar el flujo si no existe un enlace válido y guardado
- si la salida del comando no devuelve exactamente un enlace válido de Pull Request, detener inmediatamente el flujo
- si no puede escribirse `"$PR_LINK_FILE"`, detener inmediatamente el flujo
- si el enlace no puede validarse contra el patrón esperado, detener inmediatamente el flujo
- no reintentar automáticamente
- no ejecutar comandos adicionales para buscar el PR creado salvo nueva autorización explícita del usuario

Abortar si:

- no puede obtenerse correctamente el título desde `"$PR_TITLE_FILE"`
- no puede obtenerse correctamente el cuerpo desde `"$PR_FILE"`
- no puede construirse una previsualización válida del Pull Request
- ya existe un Pull Request abierto con la misma rama origen y destino
- se intenta ejecutar un comando sin haber preguntado antes al usuario
- se intenta ejecutar un comando diferente al previamente autorizado
- se intenta ejecutar más de un comando
- el comando no devuelve una URL de Pull Request válida
- la URL no coincide con el patrón `https://github.com/<owner>/<repo>/pull/<number>`
- no puede guardarse `"$PR_LINK_FILE"`
- `"$PR_LINK_FILE"` queda vacío

Salida requerida:

- mostrar la operación prevista: creación de Pull Request `release/1.Y.x -> develop`
- mostrar el título y cuerpo que se usarían
- mostrar el comando exacto que se ejecutaría para crear el Pull Request
- indicar explícitamente que no se ejecutará ningún otro comando adicional
- indicar explícitamente que no se ha ejecutado ningún comando
- avisar de que, si el comando falla o no devuelve un enlace válido de Pull Request, el flujo se detendrá inmediatamente
- preguntar al usuario antes de ejecutar la creación real del Pull Request
- tras ejecución autorizada y exitosa, mostrar el enlace del Pull Request creado
- mostrar la ruta de `"$PR_LINK_FILE"`
- indicar explícitamente que el enlace ha sido validado y guardado
- esperar autorización explícita del usuario para cualquier paso posterior

Ejemplo de comando permitido:

`gh pr create --base develop --head release/1.3.x --title "Enhance Quick Open with Hybrid Search and Persistent Cache, Redesign .gitignore Management, and Optimize Performance" --body-file "c:\Users\Developer\Desktop\@anappwilos\afav_TEST\out_tmp\1.2.40...1.3.49\24032026\151151\PR.txt"`

Reglas sobre el ejemplo:

- si este es el comando aprobado por el usuario, solo puede ejecutarse exactamente este
- si falla, detener el flujo inmediatamente
- no ejecutar después comandos como `gh pr view`, `gh pr edit`, `git status`, `git push` o similares salvo nueva autorización explícita

### 8.4 Resultado de la fase 1

Mostrar:

- rama origen
- rama destino
- fichero usado para el título del Pull Request
- fichero usado para el cuerpo del Pull Request
- fichero donde se ha guardado el enlace del Pull Request: `"$PR_LINK_FILE"`
- enlace del Pull Request creado
- confirmación de que no se ha ejecutado ningún comando sin autorización explícita
- resumen del comando ejecutado para la creación del Pull Request

Abortar si:

- no existe `"$PR_LINK_FILE"`
- `"$PR_LINK_FILE"` está vacío
- el contenido de `"$PR_LINK_FILE"` no es un enlace válido de Pull Request

Esperar confirmación explícita del usuario antes de continuar con cualquier paso posterior.
