# Textos de Merge · Caso B

Este paso continúa el flujo anterior.
Usar el contexto generado en el workflow previo.
Continuar con las variables generadas en el paso anterior.

---

## Merge

Está permitido leer `"$VAR_S1_FILE"` únicamente para obtener variables necesarias de este paso.

Está permitido leer `"$ANALYSIS_FILE"` únicamente como fuente de verdad para el contenido funcional y técnico de este paso.

No está permitido usar ninguna otra fuente.

---

## Rol

Actúa como un **Technical Lead experto en releases, GitHub Pull Requests y redacción técnica de historial Git**.

---

## Objetivo

Generar `MERGE_TITLE.txt` y `merge.txt` dentro de `"$OUTPUT_DIR"` para la integración desde `develop` hacia `"$TARGET_BRANCH"`.

- `MERGE_TITLE.txt` debe contener únicamente la frase principal del merge
- `merge.txt` debe contener únicamente el cuerpo del merge

El contenido debe reflejar consolidación técnica de release: estabilización, documentación, empaquetado y validación.

---

### 6.1 Validar directorio de salida de merge

Leer `"$VAR_S1_FILE"` para obtener:

- `OUTPUT_DIR`
- `CURRENT_BRANCH` → debe ser exactamente `develop`
- `TARGET_BRANCH` → debe cumplir exactamente `^releases/1\.[0-9]+\.0$`
- `RELEASE_VERSION` → debe cumplir exactamente `1.[0-9]+.0`

Definir:

- `MERGE_TITLE_FILE="$OUTPUT_DIR/MERGE_TITLE.txt"`
- `MERGE_FILE="$OUTPUT_DIR/merge.txt"`

Acción:

`mkdir -p "$OUTPUT_DIR"`

Abortar si:

- `OUTPUT_DIR` no existe o está vacío
- `CURRENT_BRANCH` no es exactamente `develop`
- `TARGET_BRANCH` no cumple `^releases/1\.[0-9]+\.0$`
- `RELEASE_VERSION` está vacía
- no puede crearse `"$OUTPUT_DIR"`

### 6.2 Leer análisis para merge

Leer `"$ANALYSIS_FILE"` y usarlo como única fuente de verdad para identificar exclusivamente los cambios más relevantes de la release.

Reglas:

- no usar `"$DIFF_FILE"`
- no usar archivos actuales del proyecto
- no usar historial de conversación
- no inferir cambios no escritos explícitamente en `"$ANALYSIS_FILE"`
- omitir categorías vacías
- centrar el contenido en el alcance técnico consolidado del merge

Abortar si:

- `"$ANALYSIS_FILE"` no existe
- `"$ANALYSIS_FILE"` está vacío

---

### 6.3 Generar MERGE_TITLE.txt y merge.txt

#### MERGE_TITLE.txt

**La frase principal debe ser exactamente:**

```
Prepare release <RELEASE_VERSION> for publication
```

No usar variantes como:
- `Merge pull request #...`
- `Stabilize release...`
- `Consolidate release...`

`MERGE_TITLE.txt` debe contener una única línea sin bloque markdown.

#### merge.txt

El cuerpo del merge solo debe existir si ayuda a explicar el alcance técnico consolidado.  
Si no aporta valor real, puede quedar vacío.

Formato de salida cuando existe contenido:

```markdown
- Final version alignment in package.json
- Release notes and changelog updates
- VSIX packaging adjustments
- Final fixes required for publication
```

Si el análisis aporta detalles técnicos adicionales relevantes, sustituir o complementar esas viñetas sin inventar información.

Reglas para `merge.txt`:

- `merge.txt` contiene únicamente el cuerpo del merge
- no duplicar la frase principal dentro del body
- sin secciones markdown (`##`, `###`, `Summary`)
- sin metadatos de ramas, versión ni directorio
- sin riesgos, validaciones ni contexto no explícito
- viñetas breves, una idea por línea
- comenzar cada viñeta con `- `
- no crear viñetas vacías

Abortar si:

- `MERGE_TITLE.txt` contiene más de una línea
- `MERGE_TITLE.txt` no es exactamente `Prepare release <RELEASE_VERSION> for publication`
- `merge.txt` incluye la frase principal dentro del body

---

### 6.4 Escribir MERGE_TITLE.txt y merge.txt

Crear o sobrescribir:

- `"$MERGE_TITLE_FILE"`
- `"$MERGE_FILE"`

Abortar si:

- no puede escribirse `"$MERGE_TITLE_FILE"`
- no puede escribirse `"$MERGE_FILE"`

---

### 6.5 Resultado de merge

Mostrar:

- `"$MERGE_TITLE_FILE"`
- `"$MERGE_FILE"`

Mostrar además un resumen breve indicando:

- frase principal del merge generada
- rama origen
- rama destino
- directorio de salida utilizado
- bloques principales incluidos realmente en base a `"$ANALYSIS_FILE"`
