# 6 Generación de textos de PR · Caso B

Este paso continúa el flujo anterior.
Usar el contexto generado en el workflow previo.
Continuar con las variables generadas en el paso anterior.

---

## Pull Request

Está permitido leer `"$VAR_S1_FILE"` únicamente para obtener variables necesarias de este paso.

Está permitido leer `"$ANALYSIS_FILE"` únicamente como fuente de verdad para el contenido funcional y técnico de este paso.

No está permitido usar ninguna otra fuente.

---

## Rol

Actúa como un **Technical Lead experto en releases, GitHub Pull Requests y redacción técnica de historial Git**.

---

## Objetivo

Generar `PR_TITLE.txt` y `PR.txt` dentro de `"$OUTPUT_DIR"` para una integración desde `develop` hacia `"$TARGET_BRANCH"`.

- `PR_TITLE.txt` debe contener únicamente el título del Pull Request
- `PR.txt` debe contener únicamente el cuerpo del Pull Request

---

### 5.1 Validar directorio de salida de PR

Leer `"$VAR_S1_FILE"` para obtener:

- `OUTPUT_DIR`
- `CURRENT_BRANCH` → debe ser exactamente `develop`
- `TARGET_BRANCH` → debe cumplir exactamente `^releases/1\.[0-9]+\.0$`
- `RELEASE_VERSION` → debe cumplir exactamente `1.[0-9]+.0`

Definir:

- `PR_TITLE_FILE="$OUTPUT_DIR/PR_TITLE.txt"`
- `PR_FILE="$OUTPUT_DIR/PR.txt"`

Acción:

`mkdir -p "$OUTPUT_DIR"`

Abortar si:

- `OUTPUT_DIR` no existe o está vacío
- `CURRENT_BRANCH` no es exactamente `develop`
- `TARGET_BRANCH` no cumple `^releases/1\.[0-9]+\.0$`
- `RELEASE_VERSION` está vacía o no cumple el patrón
- no puede crearse `"$OUTPUT_DIR"`

### 5.2 Leer análisis para PR

Leer `"$ANALYSIS_FILE"` y usarlo como única fuente de verdad para identificar exclusivamente:

- nuevas funcionalidades
- mejoras
- correcciones
- eliminaciones
- cambios de seguridad
- comandos nuevos o modificados enlazables en la documentación, si aparecen reflejados
- notas técnicas explícitas relevantes para la revisión del Pull Request

Reglas:

- no usar `"$DIFF_FILE"`
- no usar archivos actuales del proyecto
- no usar historial de conversación
- no inferir cambios no escritos explícitamente en `"$ANALYSIS_FILE"`
- omitir categorías vacías
- no convertir dudas o ambigüedades en hechos
- centrar el contenido en lo que cambia dentro del Pull Request
- no tratar este paso como guía de integración o post-merge

Abortar si:

- `"$ANALYSIS_FILE"` no existe
- `"$ANALYSIS_FILE"` está vacío
- `"$ANALYSIS_FILE"` no contiene información utilizable

---

### 5.3 Generar PR_TITLE.txt y PR.txt

#### PR_TITLE.txt

**El título debe ser exactamente:**

```
Prepare release <RELEASE_VERSION>
```

No añadir prefijos, variantes, sufijos ni modificaciones.  
`PR_TITLE.txt` debe contener una única línea sin bloque markdown.

#### PR.txt

Formato de salida requerido:

```markdown
## Summary

This PR prepares release <RELEASE_VERSION> for publication.

## Included scope
- Final version alignment in package.json
- Release notes and changelog updates
- VSIX packaging adjustments
- Final fixes required for publication

## Release preparation

Incluir solo las secciones reales que existan en "$ANALYSIS_FILE":

### Features
- ...

### Improvements
- ...

### Fixes
- ...

### Removals
- ...

### Security
- ...

## Validation
- npm run lint
- npm run compile
- npm run test
- VSIX generated successfully
```

Reglas para `PR.txt`:

- `PR.txt` contiene únicamente el body del Pull Request
- no duplicar el título dentro del body
- `Included scope` es un bloque fijo de orientación release; mantenerlo siempre
- `Release preparation` refleja únicamente cambios explícitos del análisis; omitir categorías vacías
- `Validation` es un bloque fijo; mantenerlo siempre
- no inventar cambios
- no escribir como si la release ya estuviera publicada
- no añadir checklist de QA no respaldado por el análisis
- no añadir riesgos, breaking changes o migraciones si no aparecen explícitamente

Abortar si:

- `PR_TITLE.txt` contiene más de una línea
- `PR_TITLE.txt` no es exactamente `Prepare release <RELEASE_VERSION>`
- `PR.txt` incluye el título dentro del body

---

### 5.4 Escribir PR_TITLE.txt y PR.txt

Crear o sobrescribir:

- `"$PR_TITLE_FILE"`
- `"$PR_FILE"`

Abortar si:

- no puede escribirse `"$PR_TITLE_FILE"`
- no puede escribirse `"$PR_FILE"`

---

### 5.5 Resultado de PR

Mostrar:

- `"$PR_TITLE_FILE"`
- `"$PR_FILE"`

Mostrar además un resumen breve indicando:

- título del Pull Request generado
- rama origen
- rama destino
- directorio de salida utilizado
- categorías incluidas realmente en base a `"$ANALYSIS_FILE"`
