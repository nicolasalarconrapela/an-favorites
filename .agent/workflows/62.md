# feature/* -> develop

## Merge

Objetivo:

Ejecutar el merge del Pull Request desde `feature/*` hacia `develop`.

Convención obligatoria para este caso:

- Merge title: debe comenzar por `Integrate `
- El merge debe resumir el bloque técnico principal integrado
- El merge no debe usar `Prepare release`, `Publish release` ni `Back-merge`

Fuentes permitidas:

- `"$VAR_S1_FILE"`
- `"$MERGE_TITLE_FILE"`
- `"$MERGE_FILE"`
- `"$PR_LINK_FILE"`

---

## 62.1 Variables requeridas

Leer desde `"$VAR_S1_FILE"`:

- `CURRENT_BRANCH`
- `TARGET_BRANCH`
- `MERGE_TITLE_FILE`
- `MERGE_FILE`
- `PR_LINK_FILE`

Abortar si:

- `CURRENT_BRANCH` no cumple `^feature/.+$`
- `TARGET_BRANCH` no es `develop`
- falta cualquiera de los ficheros requeridos

---

## 62.2 Validación del merge

Validar:

- `"$MERGE_TITLE_FILE"` existe y no está vacío
- `"$PR_LINK_FILE"` existe y no está vacío
- `"$MERGE_TITLE_FILE"` comienza por `Integrate `
- `"$MERGE_TITLE_FILE"` contiene una única línea

Reglas para `"$MERGE_FILE"`:

- puede estar vacío
- si contiene texto, debe ser solo soporte técnico breve
- no debe repetir literalmente el título del merge

---

## 62.3 Comando previsto

Definir:

- `PR_URL="$(cat "$PR_LINK_FILE")"`

Comando permitido:

```bash
gh pr merge "$PR_URL" --merge --subject "$(cat "$MERGE_TITLE_FILE")" --body-file "$MERGE_FILE"
```

Reglas:

- mostrar el comando exacto antes de ejecutar
- pedir autorización explícita antes de ejecutar
- ejecutar un único comando por vez
- si falla, detener el flujo
- no usar el mensaje automático por defecto de GitHub

---

## 62.4 Resultado esperado

Mostrar:

- PR utilizado
- rama origen
- rama destino
- título de merge aplicado
- ruta de `"$MERGE_FILE"`

Preguntar al usuario si desea continuar con el siguiente workflow.
